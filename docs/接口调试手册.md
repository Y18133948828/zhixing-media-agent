# 服务端接口调试手册

## 工作台新增接口速查

下表路径均省略 `/api/v1`，认证与归属校验规则见下文。

| 方法与路径 | 用途 |
|---|---|
| POST /auth/register、/auth/login；GET /auth/me | 本地账号和 JWT |
| PATCH /tasks/{id} | 修改 title 或 archived，归档不取消或删除任务 |
| POST /tasks/{id}/rerender | 可选 pack 和 theme，整组重渲染，返回 202 操作 |
| GET /tasks/{id}/checkpoints | 最近 50 个历史状态摘要，可传 limit，最多 100 |
| POST /tasks/{id}/fork | 传 checkpoint_id 创建独立任务副本，返回 202 新任务 |
| GET /tasks/{id}/metrics | 文本调用逐项指标和汇总；缺失 usage / 单价为 null |
| GET /tasks/{id}/stream | SSE，支持 after_id 和 Last-Event-ID |
| GET /dashboard | 当前用户创作、待审稿、完成和重写数量 |

rerender 示例：`{"theme":"dark"}`，或增加完整 CardPack 类型的 pack。完成后最新主题在 `state.task_input.theme`，最初简报保留在 `input`。原文件与历史检查点保留，资产列表和导出包使用当前代次。

fork 示例：`{"checkpoint_id":"从历史接口选择"}`。从审稿检查点复制会再次等待审稿，从完成状态复制会重新加工成属于新任务的资产；不复用原任务的下载授权。空状态不能复制。

所有业务接口都以 `/api/v1` 开头。工作台使用 `Authorization: Bearer <JWT>`，也保留 `X-API-Key` 供旧版脚本调试。两种方式对应不同数据空间：JWT 只看当前用户；API Key 只看 owner_id 为空的旧任务。不要把真实密钥写入此手册。

推荐先在 `/app/` 注册本地账号；接口方式使用 `POST /auth/register` 或 `/auth/login`，请求 `{"username":"你的用户名","password":"本地设置至少8字密码"}`，取得 access_token。Swagger Authorize 可填 HTTP Bearer 令牌；旧脚本也可只填 API Key。使用 JWT 时，提交的 operator 会被服务端替换为已认证用户名。

创建、选题、审核和重试接口立即返回 **202 Accepted**，表示操作入队，不表示 AI 已生成完成。随后轮询任务详情或操作详情。默认一个进程内消费者顺序处理任务，符合本地 Demo 的用途。

## 最短人工操作路径

在 <http://127.0.0.1:8000/docs> 通过 Authorize 输入 API Key 后，依次操作：

### 1. 创建任务

`POST /api/v1/tasks`

```json
{
  "course_category": "AI应用开发",
  "target_audience": "零基础、希望理解AI应用开发的学习者",
  "brief": "讲清楚一个具体概念，给一个可跟做的小练习，避免夸大培训效果",
  "topic_count": 4,
  "card_count": 4,
  "theme": "clean",
  "content_template": "tutorial",
  "editor_notes": "少用术语，用可验证的步骤说明",
  "sources": []
}
```

可选 `theme` 为 `clean` 或 `dark`；候选选题与图片数量均为 3–5。`sources` 可传入资料对象：`title`、可选 `url`、`excerpt`。本版使用你提供的文字，不会自动抓取 URL 内容。

保存返回的 `id`（业务 task_id）。`thread_id` 是 LangGraph 内部持久化标识，前端不用自行生成或直接操作它。

### 2. 获取候选选题并选择

轮询 `GET /api/v1/tasks/{task_id}`，直到 `status=WAITING_TOPIC_SELECTION`。

候选选题在 `state.candidate_topics`，每项含 `id`、`title`、`angle`、`audience_value`、`evidence`。同时保存最外层的 `interrupt_id`。

`POST /api/v1/tasks/{task_id}/select-topic`

```json
{
  "interrupt_id": "从当前任务详情复制",
  "topic_id": "从candidate_topics中选择的id",
  "operator": "运营同学"
}
```

不能选择不在候选列表中的 ID，不能用旧断点重复推进。

### 3. 审核长文，必要时打回

轮询任务详情，直到 `status=WAITING_ARTICLE_REVIEW`。

正文在 `state.article_draft.markdown`；标题、摘要、待核实项分别在 `title`、`digest`、`fact_checks`。`state.article_version` 从 1 开始。每次新的人工审核断点都要重新读取 `interrupt_id`。

`POST /api/v1/tasks/{task_id}/review`

```json
{
  "interrupt_id": "当前审核断点ID",
  "article_version": 1,
  "decision": "rejected",
  "feedback": "开头使用初学者能理解的例子，代码只保留最小实现",
  "operator": "运营同学"
}
```

再次等待 `WAITING_ARTICLE_REVIEW`，且 `article_version` 增加到 2，再查看新稿。只检查状态而不检查版本，可能在后台消费前读到旧稿。

确认后提交：

```json
{
  "interrupt_id": "重新读取的当前审核断点ID",
  "article_version": 2,
  "decision": "approved",
  "feedback": "已核对技术事实，确认定稿",
  "operator": "运营同学"
}
```

支持人工直接改文案：在 approved 请求里增加 `edited_article`，结构与 `article_draft` 相同，包含完整的 `title`、`digest`、`markdown`、`fact_checks`。这份定稿作为后续卡片和公众号内容的共同输入；AI 原稿和人工修改记录会分别保留。rejected 请求只能携带修改意见。

默认最多重写 10 次，由 `.env` 的 `MAX_REVISIONS` 调整；到达上限仍可提交手工定稿。

### 4. 查看图文、导出

等待 `status=READY`。这表示两个加工分支都完成并已登记资产，不表示已发布。

- `state.approved_article`：确认后的原始长文。
- `state.xhs_pack`：小红书 `title`、`caption`、`tags` 与 `slides`。
- `state.wechat_html_content`：公众号内联样式 HTML 片段。
- `GET /api/v1/tasks/{task_id}/assets`：资产列表，含带 API Key 可访问的 `download_url`。
- `GET /api/v1/assets/{asset_id}/download`：单个 PNG / HTML / Markdown / JSON。
- `GET /api/v1/tasks/{task_id}/export`：下载 ZIP，包含图片、文章、小红书配文和 manifest。

默认模板 PNG 使用准确的 3:4 比例：1242 × 1656，而非 1242 × 1660。默认不靠生图模型绘制中文，模型负责结构化提炼。可选云生图配置见 README，尚未做真实付费联调。文案事实和提炼准确性仍需发布前核查。

## 状态与前端接入约定

| status | 含义 | 前端下一步 |
|---|---|---|
| QUEUED | 操作已入队 | 显示等待，继续轮询 |
| RUNNING | 后台执行中 | 显示进度，继续轮询 |
| WAITING_TOPIC_SELECTION | 等待人工选题 | 显示候选选题并提交选择 |
| WAITING_ARTICLE_REVIEW | 等待文案审核 | 显示版本、正文、修改意见输入框 |
| READY | 图文就绪 | 查看资产、下载导出包 |
| FAILED | 操作失败 | 显示 last_error，可调用 retry |

工作台通过 `GET /tasks/{task_id}/stream?after_id=0` 读取 SSE，或在断线时轮询详情。事件先入库，客户端记录最后的 id 重连；也支持 Last-Event-ID 请求头。article_delta 是从上游 SSE 的 JSON 正文中提取的增量，最终稿仍须通过完整 JSON 校验。mock 增量明确标记 source=mock，不代表真实 token。非流式供应商只有阶段进度。

普通增量查询仍可用：`GET /tasks/{task_id}/events?after_id=0&limit=100`。SSE done 表示当前操作结束或停在人工断点，并不总是整条任务 READY。关闭进度连接不会取消数据库中的任务。

列表：`GET /tasks?limit=20&offset=0&status=WAITING_ARTICLE_REVIEW`。操作详情：`GET /jobs/{job_id}`。历史稿件与审核意见：`GET /tasks/{task_id}/revisions`。

前端图片请求需要同一账号的 JWT 或所属调试空间的 API Key，不能直接使用无认证的 `<img src>`。工作台先通过认证 fetch 获取 Blob，再创建本地对象 URL。

## 幂等与冲突

`POST /tasks`、选题、审核和重试均可带 `Idempotency-Key` 请求头，长度 1–128。一次用户操作生成一个 UUID；网络超时重发时复用同一个 UUID。

- 相同键、相同请求：返回原任务或原操作。
- 相同键、不同请求：409。
- 同一任务已有未完成操作：409。
- 断点 ID、文案版本或阶段已经更新：409，应刷新详情再操作。
- 缺少 API Key 或错误：401；输入不合法：422；任务或资产不存在：404。

省略幂等键时服务端生成随机键，适合 Swagger 手工调试；正式前端应主动发送。

## 失败与恢复

`POST /tasks/{task_id}/retry`，无需请求体。只能重试 FAILED 任务。重试沿用原操作和 LangGraph thread_id，从数据库最近成功断点继续。

程序停止时尚未确认完成的数据库任务，在下一次启动自动检查并恢复。若已到达下一人工断点，恢复逻辑不会把旧审核意见重复应用到新稿。

错误提示不会返回供应商错误正文或密钥。常见原因：接口地址或模型名错误、不支持 JSON / 流式选项、网络超时、JSON 字段不合规、卡片过满或 Chromium 未安装。已有 approved_article 和 xhs_pack 时，可以编辑卡片包并调用 rerender；本版重新渲染整组，不提供单张重绘接口。

## 课程素材与真实反馈

录入素材：`POST /knowledge`

```json
{
  "category": "AI应用开发",
  "title": "我们课程里的入门项目",
  "body": "这里填真实课程内容、已核实技术要点和案例背景，不含敏感个人信息",
  "source_url": null
}
```

查询：`GET /knowledge?category=AI应用开发`。每次创建任务从当前用户同课程最近 200 条素材中做词项相关性排序，最多选 5 条，每条最多使用 4000 字，固化到任务上下文。中文使用双字片段，英文使用词；这是小型关键词检索，不是向量 RAG。

为 READY 内容录入已人工确认的平台统计：`PUT /tasks/{task_id}/feedback`

```json
{
  "platform": "xiaohongshu",
  "views": 1000,
  "likes": 30,
  "saves": 70,
  "comments": 8,
  "observed_at": "2026-10-28T18:00:00+08:00",
  "note": "示例数字，实际请填平台后台统计；记录发布时间等观察条件"
}
```

platform 为 `xiaohongshu` 或 `wechat`。同一任务、同一平台保存最新提交的一份累计数据，PUT 会覆盖先前记录，不会累加；查询使用 `GET /tasks/{task_id}/feedback`。

新任务将参考同类课程最近 30 份账号反馈。系统不会自动采集点赞，也不会把这 30 份样本描述成平台全局趋势或证明某种内容必然受欢迎。应积累更多真实样本后再设计排序与实验。

## 配置检查

`GET /capabilities` 返回演示模式、LangGraph 版本、图片尺寸和功能范围，不返回模型密钥或数据库连接串。

`GET /health/live` 检查 Python 服务；`GET /health/ready` 检查数据库和进程内消费者。健康接口不调用付费模型，不代表供应商 API 当前可用。

本地 OpenAPI 描述：`GET /openapi.json`，可供后续前端生成类型或导入 Apifox/Postman。
