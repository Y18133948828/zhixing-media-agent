# 安装与配置

公开版默认使用火山方舟真实文字和生图服务。源码采用 MIT 许可证，使用者自行承担模型调用费用。此项目不提供模型额度，也不需要向项目作者购买会员。

## 1. 先准备这些

| 必需项 | 要做什么 | 只需配置一次 |
|---|---|---|
| Python | 安装 Python 3.11–3.14，推荐已验收的 3.13；加入 PATH | 是 |
| Node.js + npm | 安装 Node.js 22.12+；用于构建 Vue 前端 | 是 |
| PostgreSQL | 安装并启动 PostgreSQL，推荐 17；记住自己设置的管理员密码 | 是，可供多个项目复用 |
| 火山方舟 | 开通自己账号下可调用的文字模型、生图模型，准备 API Key 和两个模型 ID | 是，后续按实际用量付费 |

Python、API、AI 工作流都在本地运行；不需要 Docker、Redis、云服务器、小红书开发者账号或微信公众号开发者账号。不需要 PowerShell 7，Windows/macOS/Linux 均可使用下面的 Python 入口；当前完整验收环境是 Windows + Python 3.13 + PostgreSQL 17 + Node 22，其他系统尚未做完整端到端验收。

请从 [Python](https://www.python.org/downloads/)、[Node.js](https://nodejs.org/en/download)、[PostgreSQL](https://www.postgresql.org/download/) 官方入口安装。安装软件和模型开通由使用者自己完成；本项目不会静默重复安装数据库。

## 2. 下载，然后运行安装向导

从 GitHub 或 Gitee 下载 ZIP 并解压，终端进入仓库根目录（包含 README.md 和 scripts 的目录），执行：

```sh
python scripts/manage.py setup
```

macOS/Linux 若只有 `python3` 命令，请替换上面的 `python`。

向导会完成项目内虚拟环境、锁定的 Python 依赖、Chromium、前端依赖与构建、业务数据库迁移和 LangGraph 检查点表初始化。不会启动其他项目的数据库，也不会覆盖已有 `backend/.env`。

首次运行会询问：

1. **ARK_API_KEY**：自己的方舟 API Key，密码方式输入，不回显。
2. **ARK_TEXT_MODEL**：文字 Model ID 或 Endpoint ID。
3. **ARK_IMAGE_MODEL**：生图 Model ID 或 Endpoint ID。
4. PostgreSQL 的主机、端口、项目独立库名。
5. 数据库连接方式：已有普通账号，或使用管理员创建新库和普通账号。

推荐数据库名 `zhixing_media`。如果选择创建，管理员密码仅用于当次建库，不写入 `.env`；项目使用程序生成随机密码的普通账号。已有同名账号/库会拒绝覆盖，让你改用已有账号模式或换名。只有开发测试需要额外选择建立 `zhixing_media_test`。

一个 PostgreSQL 实例可服务多个项目，每个项目用独立数据库与账号；不必为每个 Demo 重装软件。

安装向导仅检查数据库连接，不调用付费模型。火山凭据是否有权限、配额和模型是否支持当前参数，需要第 4 步真实验证。

## 3. 启动

```sh
python scripts/manage.py start
```

打开 <http://127.0.0.1:8000/app/> 注册本地账号并登录。Swagger 文档：<http://127.0.0.1:8000/docs>。

正常使用只需这一个 Python 进程。前端由 FastAPI 提供，无需另开 Vue 开发服务器。终端按 Ctrl+C 停止程序，PostgreSQL 服务继续运行，已提交的任务与审核状态保存在数据库。

## 4. 验证自己的付费模型

先检查配置。以下命令在 **backend 目录**运行，Windows 使用 `.venv\Scripts\python.exe`，macOS/Linux 使用 `.venv/bin/python`：

```powershell
.venv\Scripts\python.exe scripts/check_volcengine.py
# 以下两条会真实调用并产生供应商用量；请先确认自己的额度和计费。
.venv\Scripts\python.exe scripts/check_volcengine.py --live-text
.venv\Scripts\python.exe scripts/check_volcengine.py --live-image
```

然后在工作台新建 3 页任务，依次验证选题、生成长文、打回修改、审核通过、3 张图片与图文包导出。真实云图片的文字、技术事实和排版仍需人工检查。云服务返回拒绝/错误时会显示失败，不会换成 Mock 假装生成成功。

完整模型配置、尺寸与排错见[火山方舟接入指南](火山方舟接入指南.md)。

## 必需配置与可选配置

安装向导保存这些必需项至本地 `backend/.env`：

```dotenv
DATABASE_MODE=shared
DATABASE_URL=postgresql://项目账号:编码后的密码@127.0.0.1:5432/项目独立库
API_KEY=向导自动生成的长随机值
LLM_PROVIDER=volcengine
IMAGE_PROVIDER=volcengine
ARK_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
ARK_API_KEY=你自己的方舟APIKey
ARK_TEXT_MODEL=你已开通的文字模型ID
ARK_IMAGE_MODEL=你已开通的生图模型ID
```

`API_KEY` 是本地应用密钥，不是火山 API Key；不要混用。手工填写 URI 密码中的 `@ # : / %` 等特殊字符时需要 URL 编码，向导会处理。不要把上面的中文示意值当成可运行配置，也不要公开自己的 `.env`。

以下全部可暂时不配：

| 可选能力 | 什么时候需要 | 对应配置 |
|---|---|---|
| 向量知识库 | 想对课程资料做语义检索 | `EMBEDDING_PROVIDER=volcengine`、`ARK_EMBEDDING_MODEL`，并为素材建立索引 |
| 调用费用估算 | 想在界面估算金额 | 输入/输出 Token 单价、每张图片单价；未配置显示未知 |
| 企业单点登录 | 已有 OIDC 认证中心 | `OIDC_*`；本地注册登录无需配置 |
| LangSmith | 需要外部追踪 | `TRACING_*`；默认关闭 |
| 备用模型、审查网关 | 有自己的服务 | `LLM_FALLBACK_*`、`CONTENT_REVIEW_*` |
| MCP | 其他本地工具要复用本项目能力 | 三个可选 stdio 入口；主程序不依赖 |

文字和图片共用方舟 Key，但该 Key 必须同时有两个模型的调用权限。Embedding 是第三个可选模型，不是首次运行要求。

## 更换电脑、更新与常见问题

- **重新下载项目**：代码不含数据库、账号、Key 或历史图片；需要自己的配置，历史记录只在原 PostgreSQL 与 `backend/storage` 中。
- **更新代码**：保留 `.env` 和存储目录，重新运行 setup（不会覆盖配置）后 start；数据库迁移会增量执行。重要数据应自行备份后升级。
- **不想从源码构建前端**：当前交付是源码仓库，需要首次安装 Node/npm；尚未提供带构建产物的桌面安装包。
- **pip/npm/Chromium 下载失败**：检查网络和代理后重试；首次安装需要网络，项目不携带依赖缓存。
- **Linux Chromium 缺系统库**：在 backend 使用 `.venv/bin/python -m playwright install --with-deps chromium`。系统包安装可能需要管理员权限。
- **中文变成方块**：安装系统中文字体（如 Noto Sans CJK）。项目不分发商业字体。
- **连接失败**：确认 PostgreSQL 已启动、端口正确、库和账号存在。不要把数据库管理员密码当成项目账号密码。
- **401/403/模型不存在**：检查方舟 Key、模型开通状态、Model ID/Endpoint ID、区域和余额。
- **模型输出不符合 schema**：确认文字模型支持足够的输出长度；必要时调整 `LLM_JSON_MODE` 或使用支持结构化输出的模型。
- **生图尺寸不支持**：默认 `1728x2304`；实际模型需支持对应参数及3:4输出，详见方舟指南。
- **8000 端口被占用**：先关闭同一项目旧进程，当前默认只监听本机 127.0.0.1:8000。

## 开发者与自动化

非交互首次安装：在自己的终端环境设置 `DATABASE_URL`、`ARK_API_KEY`、`ARK_TEXT_MODEL`、`ARK_IMAGE_MODEL`，然后运行 `python scripts/manage.py setup --non-interactive`。不要把密码放进命令行历史或提交到 CI 配置。

测试需要事先准备独立且名称以 `_test` 结尾的数据库，并在本地环境设置 `TEST_DATABASE_URL`：

```sh
python scripts/manage.py test
# 包括 Ruff、pip check、后端测试和前端重建
python scripts/manage.py check
```

自动化测试使用隔离的 Mock/HTTP 假服务，不调用付费模型。这是开发测试机制，不是另一套面向用户的免费版。Windows 原有 `scripts/*.ps1` 仍保留，首次安装建议统一使用 Python 入口。
