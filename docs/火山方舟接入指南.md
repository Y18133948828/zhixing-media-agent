# 火山方舟：豆包文字与 Seedream 生图

核对日期：2026-10-29，开源说明更新于2026-11-03。本项目已补齐方舟标准 Chat API 和图片生成 API 适配、配置与模拟协议测试。**尚未使用维护者的付费凭据完成真实调用联调；每位使用者需验证自己的 Key、模型和权限。**

## 你需要在火山控制台准备什么

1. 登录[火山方舟控制台](https://ark.volcengine.com/region:cn-beijing)，按控制台提示完成账号准备。
2. 在模型广场选择一个支持 JSON 结构化输出的豆包文本模型，用于选题、长文、卡片提炼。首版共用一个文本模型即可，`LLM_SMALL_MODEL` 留空。
3. 选择 Seedream 生图模型，确认该模型在当前项目下有调用权限和可用额度。可用版本以控制台为准；从模型详情 / 调用示例复制 Model ID，或使用你创建的 Endpoint ID。
4. 在 [API Key 管理](https://ark.volcengine.com/region:cn-beijing/apiKey) 创建方舟 API Key，确保权限覆盖两个模型。文字和图片在同一项目且权限满足时，可以共用一个 Key。也可以按需创建更小权限的 Key；本版共用配置使用一个具备两者权限的 Key。
5. 将 Key **只填进本地** `backend/.env`，不要放到前端、聊天、截图或公开仓库。

使用的是方舟标准 API `/api/v3`。控制台模型用量、额度和价格以你实际账号显示为准；本项目没有购买资源、充值或创建云数据库。PostgreSQL 继续在本机运行。

## 本地填写

以下命令从自己下载的仓库根目录执行；首次安装见[安装与配置](安装与配置.md)。

推荐由安装向导创建 `backend/.env`；手工配置时合并以下 ARK 项，并保留自己的数据库口令与应用 API_KEY。修改现有 provider 行，不要重复添加：

```dotenv
LLM_PROVIDER=volcengine
IMAGE_PROVIDER=volcengine

ARK_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
ARK_API_KEY=在本地填方舟APIKey
ARK_TEXT_MODEL=从控制台复制的文本ModelID或EndpointID
ARK_IMAGE_MODEL=从控制台复制的SeedreamModelID或EndpointID

LLM_SMALL_MODEL=
LLM_JSON_MODE=true
LLM_STREAMING=true
ARK_THINKING=disabled
ARK_IMAGE_SIZE=1728x2304
ARK_IMAGE_RESPONSE_FORMAT=b64_json
ARK_IMAGE_WATERMARK=true
IMAGE_CONCURRENCY=2
IMAGE_TIMEOUT_SECONDS=120
```

上面的中文是填写说明，不是可调用的值。不要再额外添加同名 provider 行，应修改现有行；不要用模型配置片段覆盖整个 `.env`，否则会丢失数据库连接配置。

- 方舟模式读取 `ARK_API_KEY / ARK_TEXT_MODEL / ARK_IMAGE_MODEL / ARK_BASE_URL`，不读取通用服务的 `LLM_API_KEY / LLM_MODEL / IMAGE_API_KEY / IMAGE_MODEL`。
- `LLM_SMALL_MODEL` 可选；若填写，必须同样可用该方舟 Key 调用。留空更便于首轮联调。
- 不把完整的 `/chat/completions` 或 `/images/generations` 填到 BASE_URL，程序会分别追加。也不要填 `/api/coding/v3`。
- 首版默认关闭深度思考以便生成结构化运营内容。较老模型若不接受 `thinking` 字段，可改为 `ARK_THINKING=omit`。
- 模型若不支持 `response_format`，可关闭 `LLM_JSON_MODE`，最终仍会进行 JSON 字段校验；若不支持流式，可关闭 `LLM_STREAMING`。

完整配置片段另存于 `backend/.env.volcengine.example`。它只包含模型参数，不含数据库配置，不应直接替换现有 `.env`。

## 先检查，再真实联调

Windows 终端示例（macOS/Linux 将解释器换为 `.venv/bin/python`）：

```powershell
cd backend  # 从仓库根目录进入

# 默认仅检查 Key / 模型 ID / 地址 / 图片尺寸，不发送网络请求
.\.venv\Scripts\python.exe scripts\check_volcengine.py

# 显式调用文字接口，产生模型用量，保存3个结构化选题
.\.venv\Scripts\python.exe scripts\check_volcengine.py --live-text

# 显式生成1张测试卡片，产生生图用量；不跑整套3–5页
.\.venv\Scripts\python.exe scripts\check_volcengine.py --live-image
```

真实联调仅在你主动加 live 参数后执行，结果写入 `示例成果/火山方舟联调/<时间>/`，不会自动审核或发布业务内容。瞬时网络 / 429 / 5xx 错误可能触发重试，因此不要把脚本当成一次请求精确计费承诺。

通过后，停止旧的 Python 服务，再从项目根目录执行 `python scripts/manage.py start`。打开 `/app/` 并**新建任务**验证选题、审核、卡片和导出。旧任务包含创建时状态，不建议混用测试任务和真实模型联调。

公开配置默认真实服务，需要先完成模型开通和本地配置。自动化测试中的 Mock 与假 HTTP 服务仅用于开发验证，不代表真实模型效果。

## 这次对接口做了哪些适配

| 内容 | 实现 |
|---|---|
| 文本接口 | `POST /api/v3/chat/completions`，Bearer API Key，Model ID / Endpoint ID |
| JSON 与流式 | JSON object + 本地 Pydantic 校验，按配置关闭思考，消费上游 SSE / usage |
| 图片接口 | `POST /api/v3/images/generations`，不发送通用 OpenAI 的 n 参数 |
| 页序与并发 | 每页一个请求，并发上限2；按原卡片页序返回，失败时取消尚未完成的协程 |
| 图像尺寸 | 显式 1728×2304，精确3:4；不使用模型自行决定比例的 2K 字符串 |
| 图片结果 | 默认 Base64；可改 url，及时下载到本地，不依赖临时链接长期可用 |
| 水印 | 默认保留供应商水印开关 true |
| 异常 | 检查 HTTP 状态、整体错误和单图错误；内容拒绝不换成无关图片，不把供应商原始错误正文暴露给前端 |
| 用量 | 文本 Token 来自供应商响应；图片按页记录，可按配置的单张价格估算，最终以方舟账单为准 |

原来的 1536×2048 通用默认尺寸，总像素为 3,145,728，低于 Seedream 4.5 文档要求的 3,686,400。因此方舟单独使用 1728×2304（3,981,312 像素），这也是官方 2K 竖向3:4参考尺寸。选择其他型号或更高分辨率时仍需核对具体模型约束。

模板图片仍为 1242×1656；方舟图片使用 API 实际返回的3:4尺寸，不静默裁切。即使 Seedream 支持中文生成，也可能出现文字或代码错误，发布前需人工核对。技术代码较多时，本地模板仍是可切换选项；不会在云生图失败时自动冒充成功。

## 常见问题

| 现象 | 优先检查 |
|---|---|
| 本地提示缺少 ARK_API_KEY / 模型 ID | 填写的是原 `.env` 的 ARK 项，当前终端环境变量是否覆盖文件 |
| HTTP 401 / 403 | 方舟 API Key 是否有效、项目与模型权限是否匹配；不是账号 AK/SK |
| HTTP 404 | BASE_URL 与 Model ID / Endpoint ID 是否正确，模型是否仍可用 |
| HTTP 400 | 模型参数支持范围，尤其 thinking、JSON 模式、图片尺寸与型号 |
| HTTP 429 | 控制台限流与可用额度；降低并发后重试 |
| 返回200但没有图片 | 可能有单图错误 / 内容拒绝，不能把 HTTP 200 当成生图成功 |
| 图片不是3:4 | 核对模型支持和 ARK_IMAGE_SIZE；程序会明确失败而非裁剪 |
| Key 已填但工作台仍显示演示 | 修改两个 provider 行后重启 Python，并新建任务 |
